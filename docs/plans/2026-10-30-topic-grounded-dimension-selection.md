# 议论文题目关联维度生成优化实施计划

> **For Codex:** 按任务逐项执行本计划；实施前确认工作区仍位于 `latest_version/adaptive-english-writing`。

**目标：** 让议论文智能体根据完整作文题目动态推荐三个宽泛、贴题、互不重复且不预设论点的思考视角。

**架构：** 在现有 `fetchInspirationCards` 生成链路中先解析题目，从可迁移的宽泛视角菜单中动态选三项并生成与本题相关的中文说明，再由独立模型请求复核整组卡片；失败时最多重生成一次。保持现有 JSON 数据结构，不固定三项组合，避免影响记叙文规划、卡片存档和后续语言支架。

**技术栈：** React、TypeScript、现有 `geminiService.ts` / Gemini JSON Schema 调用。

---

## 设计选择

| 方案 | 做法 | 优缺点 |
| --- | --- | --- |
| A. 单次生成并内置复核 | 一个模型请求内完成题目解析、候选生成、筛选与复核 | 改动小，但实测出现题目与说明脱节 |
| B. 两阶段生成与评审（当前流程） | 第一次生成候选维度，第二次独立模型调用审查；失败后最多重试一次 | 强化贴题与粒度检查，但增加延迟、成本及调用失败点 |
| C. 受控宽泛视角菜单（当前标题约束） | 将标题限制在可迁移的分析领域内，模型仍根据题目选三项并写说明，独立复核贴题性 | 避免把题目词或比较指标误当视角；需持续检查菜单覆盖面与说明质量 |

已先实施 A。随后实际使用中出现“校内资源”题目配上 Environmental / Cultural / Psychological，中文说明却讨论教育科技的失败样例。因此改用 B：生成后独立核对整组卡片，失败时重生成一次；第二次仍不合格则提示重试，不保存卡片。

四道题目的后续实测表明：贴题已有改善，但“资源知晓—主动使用—资源整合”形成操作步骤；线上学习的灵活性、互动、资源可及性形成比较指标；平衡学业与活动的时间管理、个人成长、学业压力接近现成段落论点。已将这些情况纳入生成与独立复核的粒度标准。信息安全题从个人、企业、政府三个主体切入较有区分度，但具体标题仍需保持开放。

再次用同样四题测试后，生成结果又出现 `Balance / Students / Long-term`、`Learning / Interaction / Flexibility`、`Students / Resources / Institution`：虽然标题变短，但部分只是复述题目对象、任务或比较指标。由此从完全自由拟标题改为受控宽泛视角菜单，按题目动态选择并用中文说明解释本题关联；菜单不规定每题都用同三项。学生自选补充视角仍保留自由输入。独立复核增加“是否只复述题目”检查，代码也会拒绝菜单外的初始标签。

## 统一筛选标准

每个候选维度按以下标准检查：

1. **贴题：** 能直接连接题目的讨论对象、任务或核心关系；牵强关联项淘汰。
2. **区分：** 三个维度分别提供不同的讨论入口，不以近义词重复同一层面。
3. **易懂：** 标题使用学生熟悉的词；允许贴题且有中文语境说明的单词标签，避免晦涩抽象词。
4. **开放：** 是分析视角，不包含立场、结论、建议、例证或现成分论点。
5. **适度宽泛：** 一个维度应能容纳多种学生自己提出的想法；不细化成单一原因、影响、优劣、方法、比较指标或写作步骤。
6. **整组多样：** 三个维度不能是同一过程的三个阶段、同一层面的三个细分，或几乎可以直接充当三段正文提纲。宽泛类别由题目动态筛选，不固定套用通用三项。
7. **有效命名：** 标题应是可迁移的分析领域，不直接复制题目对象、写作任务或结果；若同词在题目中出现，中文说明必须体现它能开启不同的分析层面。

## 实施任务

### Task 1：确认题目输入完整性与文体边界

**检查文件：** `modules/SocraticCoach.tsx`、题目输入组件（实施时根据调用处追踪 `UserInput.topic` 来源）、`types.ts`。

- 追踪用户输入的完整题干是否原样传入 `fetchInspirationCards(input.topic)`；区分页面标题截断展示与实际模型输入。
- 确认记叙文仍由 `fetchNarrativePlanningCards` 处理，不改变其场景、行动、结果三段规划。
- 只有在发现输入被截断或丢失任务说明时，才改对应数据传递；不改题目显示方式。

### Task 2：重写议论文维度生成提示

**修改文件：** `services/geminiService.ts` 中 `fetchInspirationCards`（当前约第 789–841 行）。

- 明确要求模型先识别题目对象、写作任务、核心关系和情境限制。
- 要求模型按统一标准筛选三个维度，不得固定套用 Personal / Social / Economic，也不得为了凑数采用无关视角。
- 明确每个维度只能是宽泛思考入口，禁止生成结论或现成论点。
- 约束维度标题用清楚、自然的英文短语；必要时用已有字段提供简短中文说明，说明范围但不引导立场。
- 检查当前 `thinkingExpansion` 指令：现行提示把拓展写成具体论点。本次改为中性问题或探究方向，避免初始维度阶段就替学生生成分论点；保留现有 JSON Schema 字段，确保历史数据兼容。
- 请求格式继续符合当前 `Schema`，不将模型分析过程暴露给学生。
- 根据上述失败样例，增加独立的题目相关性核对：同时检查英文维度名、中文说明和引导问题；最多重生成一次，并在校验失败时阻止卡片进入存档。

### Task 3：处理生成结果并保持界面兼容

**检查文件：** `types.ts`、`SocraticCoach.tsx`、渲染灵感卡片的组件（实施时用 `rg` 定位 `InspirationCard` 的实际渲染处）。

- 核对 `dimension` 等必需字段仍能通过现有解析器和存档结构。
- 若增加维度范围说明，确认卡片布局能清楚显示且不会把它误显示为立场或结论；不为本次优化重做页面布局。
- 不改变“完成任意两个维度即可进入组合成文”、用户自选更多维度、维度草稿保存和语言支架行为。

### Task 4：用代表性题目做人工回归评估

不新增或执行自动化测试。实施后人工检查模型实际输出，题目至少覆盖：

- 校园资源实践建议题：`how students can make the best use of on-campus resources for academic development`。
- 线上学习与传统课堂比较题。
- 传统文化与全球化题。
- AI 对就业影响题。
- 含完整指令、固定开头句或字数要求的 CET-6 题干。

**通过标准：** 每题返回恰好三个视角；每个视角可从题干明确解释其相关性；三者有明显区分；学生无需猜测抽象词含义；输出没有直接替学生给出分论点；固定开头、字数等指令不被误当成维度。另确认记叙文生成逻辑未被触及。

## 范围外

- 不改记叙文三卡设计。
- 不改评分量规、历史记录、Supabase 表结构、草稿保存和部署配置。
- 不规定每题固定使用哪三个视角；受控菜单仅约束初始推荐标签，学生自选补充视角仍可超出菜单。
- 题目相关性与粒度问题已有实测证据，因此当前使用独立复核调用；后续需用真实题目观察其稳定性、额外延迟与失败率。
